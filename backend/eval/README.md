# 评测数据集 —— 填写与跑分说明

评测集是给 LLM 用的**考卷 + 标准答案**。Agent 的输出每次措辞都不一样,没法用
`assert 输出 == "未戴安全帽"` 这种普通断言;评测集的作用是把「感觉还行」换成一个
**可复现的数字**,让你改完提示词能立刻知道是变好还是变坏。

三套门槛已钉在 `backend/src/gyt/config.py`,**跑分脚本要从那里读,不许再写一遍数字**:

| 套 | 门槛 | 配置项 | 谁准备数据 | 何时验收 |
|---|---|---|---|---|
| 路由 routing | ≥90% | `eval_threshold_routing` | 你 | W3 末 |
| 安全 safety | ≥80% | `eval_threshold_safety` | 你 | **W2 末** |
| 知识 rag | ≥80% | `eval_threshold_rag` | 队友 | **W2 末** |

---

## 一、三条铁律(违反了这个评测集就是废的)

**1. 标准答案必须人来定。** 让 AI 生成标准答案再拿去考 AI,等于自己给自己判卷,
分数没有任何意义。仓库里现有的示例行**数字全是编的**,标注前必须逐条替换成
你们真实文档 / 真实照片里的内容。

**2. 必须有负向与对照样本。** 30 张全是明显违规的照片,一个只会喊「有违规」的
模型也能拿 100 分 —— 它其实什么都没学会。所以三套里都留了这类行:
安全集的 `compliant`(合规对照)与 `not_site`(非工地干扰项)、
知识集的 `no_answer`(知识库查不到,期望它承认查不到而不是编)、
路由集的 `none`(闲聊,不该派给任何子 Agent)。
**你想让模型不犯的错,数据集里就必须有那种情况。**

**3. 数量到位再谈调优。** 路由 20 条、安全 30 张、知识 20 组是方案定的下限。
样本太少时百分比会剧烈跳动(10 条里错 1 条就是 10 个百分点),那种数字指导不了任何决策。

## 二、怎么填

### routing.csv —— 测 Supervisor 派活准不准

| 列 | 说明 |
|---|---|
| `id` | R01、R02……唯一即可 |
| `type` | `positive` 正常请求 / `none` 不该派给任何子 Agent / `ambiguous` 信息不足应追问 |
| `user_input` | **工人真会说的话**,不是规范书面语。多写几种同义说法 |
| `expected_agent` | `safety` / `knowledge` / `schedule` / `cad` / `report` / `none` |
| `note` | 这条测什么,可空 |

判分:实际派给的 Agent == `expected_agent` 即算对。`none` 表示 supervisor 应自己回答或追问。

> 填的时候别只写标准问法。真实用户会说「瞅瞅这照片有事没」,模型能不能路由对这种,
> 才是路由评测的意义。

### safety.csv —— 测识图准不准

| 列 | 说明 |
|---|---|
| `id` | S01、S02…… |
| `type` | `positive` 违规 / `compliant` 合规 / `hard` 难例 / `not_site` 非工地干扰项 |
| `image` | 文件名,照片放 `data/demo/photos/` |
| `label` | `violation` / `compliant` / `not_site` |
| `violations` | **只能从下面的受控词表里选**,多个用 `;` 分隔;非违规行留空 |
| `note` | 标注理由,可空 |

**违规项受控词表(定死,不许自由发挥):**

```
未戴安全帽 · 未穿反光衣 · 高空作业未系安全带 · 临边无防护
消防通道堵塞 · 材料堆放混乱 · 用电隐患 · 动火作业无监护
```

> **这份词表同时是 Safety Agent 提示词的输出约束** —— `agents/safety/prompt.md`
> 必须要求模型只从这八个里选。标注用的词和模型输出的词对不上,判分就永远是错的。
> 词表要改,两边一起改。

建议配比(共 30 张):违规 15 · 合规 7 · 难例 5 · 非工地 3。

### rag.csv —— 测检索准不准、有没有编造

| 列 | 说明 |
|---|---|
| `id` | K01、K02…… |
| `type` | `positive` 单要点 / `multi_point` 多要点 / `no_answer` 知识库查不到 |
| `question` | 工人会问的话 |
| `expected_answer_points` | 答案要点,多个用 `;` 分隔。**抄原文关键信息,别自己转述** |
| `expected_source` | 文档文件名,规范放 `data/demo/docs/` |
| `expected_page` | 页码,可写 `23` 或范围 `12-14` |
| `note` | 可空 |

判分:**答案要点命中 且 (source + page) 命中,两个都对才算对。**
只对一半不给分 —— 「答案对但引用错」说明它是猜的,不是查的,而查得到出处正是 RAG 的全部价值。

`no_answer` 行:后四列全部留空。期望模型明确说「知识库里没有依据」,**编造即判错**。

## 三、怎么跑

> 跑分脚本 `runner.py` **尚未实现**,是 W2 第一天的活(见 `docs/W2_执行计划.html` 前置 A2)。
> 它是共享基座,由一个人搭、两人共用 —— 各写各的会得到两套不可横向比较的口径。

实现时要满足的契约:

- 读 `datasets/*.csv`,编码用 `utf-8-sig`(这样 Excel 存出来带 BOM 的文件也能读)
- 逐条调被测 Agent → 交给该套的判分函数 → 汇总
- 输出:总分 + **逐条明细**(哪几条挂了、模型实际输出是什么)。
  只给一个总分是没用的 —— 调提示词需要知道具体错在哪
- 低于门槛 **exit 非 0**,好让 CI 能拦门
- 门槛从 `config.py` 的 `eval_threshold_*` 读
- `make eval` 跑全部;CI 的 eval job 取消注释后生效

```bash
make eval              # 跑全部三套
make eval SUITE=safety # 只跑一套(实现时支持)
```

## 四、常见坑

- **Excel 存 CSV 会把 UTF-8 搞坏。** 用 Numbers、VS Code 或 Google Sheets;
  非用 Excel 不可就存成「CSV UTF-8」格式。
- **字段里有逗号要用双引号包起来**,否则列会串位。
- **照片文件名别用中文和空格**,`photo_01.jpg` 这种最省事。
- **标注是滚动做的,不是最后一天做的。** 它是 W2 末验收的硬前提,
  周一开始每天标几条,周四才动手就来不及了。
- **改了受控词表 / 数据集格式,记得同步改提示词和跑分脚本**,三者是一套东西。

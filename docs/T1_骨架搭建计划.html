00b踩掉的四个坑(给三个月后的你)

这四个都不是"环境噪音",每一个都会原样咬到队友。共同点:报错文案把人往错误方向带。

坑 1 · hf-mirror.com 已死,但死得很隐蔽
镜像构建在下载权重那步必失败,报 LocalEntryNotFoundError,原文写 "Please check your connection" —— 于是人会去查一晚上网络。真相是这个域名还活着、能连通、甚至返回 200,但它已不再镜像内容, 对 /api/models/... 只回一个 308 跳转到 huggingface.co,huggingface_hub 的元数据探测拿不到结果。
判定方法:curl -sI <源>/api/models/BAAI/bge-m3 | head -3,看到 308 且 Location 指向别的域名 = 这个源已失效。
已修:默认改官方源,三步排查法写进 backend/README.md。
坑 2 · 同一常量硬编码三处,只改一处等于没改
下载源同时写在 backend/Dockerfile 的 ARG、docker-compose.yml 的 build args、.env.example 里。 我只改了 Dockerfile,构建照样红 —— 后两个把修改覆盖回去了。这是 DRY 违规最典型的咬人方式。
已修:.env.example 那行默认注释掉并写明"填了会覆盖验证过的默认值"; 另两处保留(compose 读不到 Dockerfile 的 ARG 默认值,技术上无法消除)但都加了"改一处必须改两处"的交叉引用。
坑 3 · workflow 文件不合法时,CI 自己抓不到
首次 push 后 CI 0 秒失败,不产生任何 job,check-runs API 查不到注解, GitHub 只给一句 "likely failed because of a workflow file issue"。 actionlint 一句话定位:${{ runner.temp }} 写在了 job 级 env: 里, 而 runner 上下文只在 step 级可用。job 级可用的只有 github / inputs / matrix / needs / secrets / strategy / vars。
关键认知:文件不合法时 workflow 压根不会运行,所以靠 CI 检查 CI 是不可能的,必须本地拦。
已修:改用 ${{ github.workspace }},并新增 make lint-ci(docker 跑 actionlint), 改过 .github/workflows/ 后必跑。
坑 4 · 全局 npm registry 指向已废弃域名(影响整台机器)
/usr/local/etc/npmrc 里设的是 registry.npm.taobao.org —— 该域名 2021 年就迁走, 现在证书已过期。每个包 CERT_HAS_EXPIRED 后重试 1 分钟,实测 卡一小时零下载, 而 node_modules 一直是 0B(pnpm 先下到全局 store 再链接,所以这个现象很容易被误判成"正常下载中")。
已修:改为其官方继任者 registry.npmmirror.com,顺手删掉同样失效的 disturl。 改后 pnpm install 50 秒完成。原文件备份在 /usr/local/etc/npmrc.bak-20260806。

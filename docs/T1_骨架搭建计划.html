01目标与验收

T1 做完后,任何一台装了 Docker 的新机器上:git clone → 填 .env → docker compose up → 打开 localhost:3000 就能和 Supervisor 对话(此时只有一个占位 Agent)。这是 W1 验收项,也是后面 5 个 Agent 全部往上挂的地基。

#验收项(全部可自动化检查)对应
V1docker compose up 冷启动 → chat-ui 首条消息可答,全程零下载(权重已在镜像内)E2E#7 冷启动冒烟
V2uv run pytest 全绿,覆盖率门槛 ≥80% 生效(骨架期代码少,门槛照设)D14
V3GitHub Actions 首条流水线绿:test + e2e 两个 jobCI
V4chat-ui 中能看到工具调用过程可视化与流式输出D17 随案项
V5.env 不在 git 内;.env.example 有两家 API Key 占位安全基线

03镜像构建流水线(权重预烧,复审 D1 决议)

backend/Dockerfile(多阶段)
┌─────────────┐   ┌──────────────────┐   ┌───────────────────────────┐   ┌───────────┐
│ S: base      │──▶│ S: deps           │──▶│ S: models                  │──▶│ S: app     │
│ python:3.11  │   │ uv sync --frozen  │   │ ENV HF_ENDPOINT=           │   │ COPY src/  │
│ -slim        │   │ (依赖层缓存)        │   │   https://hf-mirror.com    │   │ CMD serve  │
└─────────────┘   └──────────────────┘   │ RUN 下载 BAAI/bge-m3        │   └───────────┘
                                          │ → 权重固化进镜像层(~2.2GB)  │
                                          └───────────────────────────┘
要点:① models 层独立,改业务代码不触发权重重下 ② 国内镜像源,构建不翻墙
     ③ 首次构建约 10-20 分钟属正常,之后层缓存秒级 ④ 镜像总体积 ~4GB,属预期

05分步执行(S1-S7,每步带验收)

S1 · 目录与依赖底座(15min)

建目录树;uv init + 依赖:langgraph langgraph-supervisor langchain-openai pydantic-settings python-dotenv,dev 组:pytest pytest-cov pytest-asyncio langgraph-cli[inmem];写 .env.example;把 4 个文档挪入 docs/。
验收:uv sync 成功;git status 干净可提交

S2 · core 四件套 + 单测(45min,基座即 DRY 红线)

llm.py:双供应商工厂(deepseek base_url / moonshot base_url,从 config 读模型名)+ 重试退避 + 内容哈希缓存(键含 prompt 版本);errors.py 信封;artifacts.py 注册/读取/路径穿越拒绝;base_agent.py 薄工厂。同步写单测(mock API,不真调)。
验收:pytest 全绿,coverage ≥80%

S3 · 最小 Supervisor 跑通(30min)

graph.py:langgraph-supervisor + 一个 ping_agent(回声占位);recursion_limit=8 熔断进 config;langgraph.json 指向 graph。
验收:uv run langgraph dev 起在 :2024,curl 能拿到流式回复(需 DEEPSEEK key)

S4 · 前端接入(20min)

clone langchain-ai/agent-chat-ui 到 frontend/;.env 指向 http://localhost:2024 与 graph id;标题/主色改成工友通。
验收:localhost:3000 发消息 → 流式回复 + 能看到 supervisor→ping_agent 的工具调用轨迹(V4)

S5 · Dockerfile + compose(30min)

按 §03 四阶段写 backend/Dockerfile(models 层预烧 BGE-M3,HF_ENDPOINT 走国内镜像);frontend 用官方 Dockerfile;docker-compose.yml 两服务 + data 卷 + env_file。
验收:docker compose up 后 3000 可对话;docker compose down 再 up 不重新下权重

S6 · CI 流水线(20min)

.github/workflows/ci.yml:job① test = uv sync → pytest --cov=gyt --cov-fail-under=80;job② e2e = 起服务跑冒烟(W1 期先跑 dev 模式冒烟,W3 接 Playwright 全量)。评测 job 占位注释,W2 启用。
验收:push 后 Actions 两个 job 全绿(V3)

S7 · 冷启动冒烟 E2E(20min,复审 D1 决议)

tests/e2e/test_cold_start.py:compose up → 轮询后端就绪 → 发一条消息断言拿到流式回复 → 校验容器日志无 "Downloading"(证明零下载)。
验收:本地跑通;W4 彩排前它就是每日回归

08风险与注意

  • 镜像体积 ~4GB、首次构建 10-20 分钟:预期内,不要中途放弃;models 层缓存后不再重下。
  • API Key:两家各申请一个 key 放 .env;.env 已在 .gitignore,提交前 git status 确认它不在列表里。
  • agent-chat-ui 尽量少改:只动品牌与配置;改多了以后跟上游同步困难。
  • S3 需要真实 DEEPSEEK key 才能看到回复:没 key 前单测照跑(全 mock),联调等 key。
  • Windows 队友:如 Y 用 Windows,统一走 Docker 或 WSL2,避免路径/编码差异。
完成定义:V1-V5 全绿即 T1 关闭,进入 W2(X:Knowledge Agent;Y:Safety Agent)。任何范围外的新想法 → TODOS.md,不进 T1。

## 現在為什麼「繁瑣、不明確」

以「拍一張照到監理簽發通知單」計,現在要 **13 個動作**:
拍照 → 發送 → 讀一段文字(隱患編號夾在句子裏)→ 找到底欄 12px 的「隱患」→ 開面板 → 在 7 條待確認裏找那兩條 → 勾選 → 確認 → 切「在辦」→ 再找那條 → 點「處置」→ 面對 3 個輸入框 + 5 顆按鈕 → 選日期 → 簽發。

三個根因(截圖見審查報告 FINDING-001/002/003):
1. **結果是文字,隱患卻要到別處去找。** 系統其實已經登記完了,對話裏卻沒有任何可點的東西。
2. **每個對話頁頂上都是四張 Agent 卡。** 手機 812px 高的屏,卡 330px + 輸入條 230px,對話只剩 250px。
3. **處置區把所有動作的輸入框一次全擺出來。** 人還沒說要幹什麼,先看到「整改期限」「關掉的原因」「挪到哪個工地」三格。

## 提案(6 個動作)

拍照 → 發送 → **卡上點「確認是隱患」** → **「去監理處置 →」** → 面板該條只露「簽發處置文書」→ 確認簽發(日期已預填)。

### ① 拍完照:結果就是一張能點的卡
- 回答上方一張**隱患卡**:每條 = 級別徽章 / 名稱 / 編號 / 「確認是隱患」「不是隱患」;卡底「去監理處置 →」。
- 數據源:**不等工具返回**(那條路被 supervisor 的 `output_mode="last_message"` 丟掉,CLAUDE.md 有記)。用戶消息裏有 `photo_id`,卡自己打 `GET /supervision/hazards?scope=全部` 按行載荷裏的 `photo_id` 過濾。
- 對話頁頂上四張卡縮成**一行狀態**(`調度中樞 · 識隱患 正在看… ▸`),點開才展開;空白首頁保留四張。
- 六行「轉給 / 交回」+ 計時表折進回答底下**一行**「過程 7 步 · 30.4s ▸」;「隱藏中間步驟」開關搬進展開裏(默認折疊 = 原來的隱藏)。

### ② 監理面板:先選動作,再填那一格
- 一條隱患只露**一顆主按鈕**(= 步驟條當前步)+「更多 ▾」;主按鈕點了才在下面展開該動作的那一兩格(簽發 → 日期 + 簽發人;關掉 → 原因;改工地 → 下拉;登記複查 → 照片)。
- 「更多 ▾」收:改判級別、關掉(不出文書)、改整改期限、改工地、否決。
- 徽章從四顆減到兩顆(級別 + 狀態);「現場檔」進定級面板當參考;「未歸工地」併進編號行。

### ③ 首頁與輸入條
- 輸入條 8 個控件 → 5 個:拍照(主)/「＋」上傳 / 🛡 隱患(帶待確認數)/「⋯」(打卡、記錄)/ 發送。
- 同一個 Agent 只用一個名字:「識隱患」(現在還叫「安全巡檢員」「巡檢出記錄」「inspection」)。
